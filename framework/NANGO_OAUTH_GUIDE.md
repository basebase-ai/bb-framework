# Nango OAuth Integration Guide

Basebase uses **Nango** for OAuth integrations, providing instant access to **500+ APIs** including Google, Salesforce, HubSpot, Notion, Slack, Figma, and more.

Nango handles the entire OAuth flow, token storage, and automatic token refresh. You never have to worry about expired tokens.

## Architecture Overview

We use Nango's **Connect Session Token** approach (the secure, recommended method):

```
1. User clicks "Connect HubSpot"
   ↓
2. Frontend calls backend function (nangoCreateSession)
   ↓
3. Backend creates a short-lived session token via Nango API
   ↓
4. Frontend receives token, opens Nango OAuth popup
   ↓
5. User authorizes in popup (HubSpot consent screen)
   ↓
6. Nango stores tokens, generates a connectionId
   ↓
7. Frontend refreshes status (isConnected = true)
   ↓
8. Backend functions can now get tokens via getOAuthToken()
```

**Key Points:**

- No public key exposed in frontend code (more secure)
- Connection IDs are randomly generated by Nango (not user IDs)
- Users are identified by `endUserId` (your Firebase UID)
- Tokens are stored and refreshed automatically by Nango

## Quick Start

### 1. Setup Nango Account

1. Sign up at [nango.dev](https://nango.dev) (free tier available)
2. Go to **Integrations** and enable the providers you need (e.g., Google Mail, HubSpot)
3. Configure OAuth credentials for each provider in Nango dashboard
4. Copy your **Secret Key** from Environment Settings

### 2. Configure Environment Variables

```bash
# Backend secrets only - no frontend keys needed!
# Add via your secrets management system
NANGO_SECRET_KEY=your_nango_secret_key
```

> **Note:** Unlike the deprecated public key approach, Connect Sessions don't require any frontend environment variables. The session token is fetched securely from your backend.

### 3. Install Dependencies

```bash
npm install
```

### 4. Deploy Nango Functions

```bash
npm run function:commit nangoCreateSession
npm run function:commit nangoCheckConnection
npm run function:commit nangoGetToken
npm run function:commit nangoDeleteConnection
```

## Frontend Usage

### Basic Connection Flow

```jsx
import {
  useNangoOAuth,
  NangoIntegrations,
} from "../../../framework/hooks/useNangoOAuth.js";

function SettingsPanel() {
  const { isConnected, connect, disconnect, loading, error } = useNangoOAuth(
    NangoIntegrations.hubspot
  );

  return (
    <Stack>
      <Group>
        <Text>HubSpot</Text>
        {isConnected && <Badge color="green">Connected</Badge>}
      </Group>

      <Group>
        <Button onClick={connect} loading={loading}>
          {isConnected ? "Reconnect" : "Connect HubSpot"}
        </Button>

        {isConnected && (
          <Button variant="subtle" onClick={disconnect}>
            Disconnect
          </Button>
        )}
      </Group>

      {error && <Alert color="red">{error.message}</Alert>}
    </Stack>
  );
}
```

### What Happens When `connect()` is Called

1. **Backend call**: `nangoCreateSession` is called to get a session token
2. **Popup opens**: Nango SDK opens the OAuth provider's consent screen
3. **User authorizes**: User grants permissions in the popup
4. **Connection created**: Nango stores tokens and creates a connection
5. **Status updates**: `isConnected` becomes `true`

### Multiple Integrations

```jsx
function IntegrationsPage() {
  const gmail = useNangoOAuth(NangoIntegrations.googleMail);
  const salesforce = useNangoOAuth(NangoIntegrations.salesforce);
  const slack = useNangoOAuth(NangoIntegrations.slack);
  const notion = useNangoOAuth(NangoIntegrations.notion);

  const integrations = [
    { name: "Gmail", hook: gmail, icon: IconMail },
    { name: "Salesforce", hook: salesforce, icon: IconBriefcase },
    { name: "Slack", hook: slack, icon: IconBrandSlack },
    { name: "Notion", hook: notion, icon: IconNote },
  ];

  return (
    <Stack>
      {integrations.map(({ name, hook, icon: Icon }) => (
        <Paper key={name} p="md" withBorder>
          <Group justify="space-between">
            <Group>
              <Icon size={24} />
              <Text>{name}</Text>
              {hook.isConnected && <Badge color="green">Connected</Badge>}
            </Group>
            <Button
              onClick={hook.connect}
              loading={hook.loading}
              variant={hook.isConnected ? "light" : "filled"}
            >
              {hook.isConnected ? "Reconnect" : "Connect"}
            </Button>
          </Group>
        </Paper>
      ))}
    </Stack>
  );
}
```

## Backend Usage

### Using OAuth Tokens in Cloud Functions

```javascript
// functions/syncHubspotContacts.js
const { getOAuthToken, isOAuthConnected } = require("./lib/nango-utils.js");

module.exports = async function (params, context) {
  const userId = context.auth.uid;

  // Check if user has connected HubSpot
  if (!(await isOAuthConnected(userId, "hubspot", context))) {
    throw new Error("Please connect HubSpot first in Settings");
  }

  // Get valid access token (Nango handles refresh automatically)
  const token = await getOAuthToken(userId, "hubspot", context);

  // Call HubSpot API
  const response = await context.http.get(
    "https://api.hubapi.com/crm/v3/objects/contacts",
    {
      headers: {
        Authorization: `Bearer ${token}`,
        "Content-Type": "application/json",
      },
    }
  );

  return {
    success: true,
    contacts: response.data.results,
  };
};
```

### Available Utility Functions

```javascript
const {
  getOAuthToken, // Get valid access token (auto-refreshes)
  isOAuthConnected, // Check if user has connected
  getConnections, // Get all user's connections
  getConnection, // Get full connection details
  findConnection, // Find connection by user + integration
} = require("./lib/nango-utils.js");

// Get access token (auto-refreshes if expired)
const token = await getOAuthToken(userId, "google-mail", context);

// Check connection status
const connected = await isOAuthConnected(userId, "salesforce", context);

// List all user's connections
const connections = await getConnections(userId, context);
// Returns: [{ integrationId: "hubspot", connectionId: "conn_xxx", createdAt: "..." }]
```

### How Token Lookup Works

Since Nango generates random connection IDs, we look up connections by `endUserId`:

```javascript
// Behind the scenes, nango-utils does:
// 1. GET /connections?endUserId=<firebase-uid>&integrationId=<integration>
// 2. GET /connections/<connectionId>?provider_config_key=<integration>
// 3. Return credentials.access_token
```

## Nango API Reference

Our functions use these Nango REST API endpoints:

| Operation         | Endpoint                                                     | Description                     |
| ----------------- | ------------------------------------------------------------ | ------------------------------- |
| Create session    | `POST /connect/sessions`                                     | Get short-lived token for OAuth |
| List connections  | `GET /connections?endUserId=<id>`                            | Find user's connections         |
| Get connection    | `GET /connections/<id>?provider_config_key=<integration>`    | Get credentials                 |
| Delete connection | `DELETE /connections/<id>?provider_config_key=<integration>` | Revoke access                   |

## Troubleshooting

### "NANGO_SECRET_KEY not configured"

Add the secret key to your backend secrets management system. Find it in Nango dashboard under **Environment Settings**.

### "User has not connected [integration]"

The user needs to complete the OAuth flow first. Show a connect button in your UI.

### OAuth popup blocked

Nango uses a popup for OAuth. Users may need to allow popups for your site.

### "Invalid integration ID"

Make sure the integration is enabled in your Nango dashboard and the ID matches exactly.

### "Failed to create Connect session"

Check that:

1. `NANGO_SECRET_KEY` is set correctly
2. The integration is enabled in Nango dashboard
3. Your Nango account is active

## Security Notes

- **Secret Key** (`NANGO_SECRET_KEY`): Keep secret, only use in backend functions
- **No frontend keys**: Connect Sessions don't expose any keys in frontend code
- **Session tokens**: Short-lived (30 minutes), single-use
- **Connection IDs**: Randomly generated by Nango for security
- Tokens are stored securely by Nango, never exposed to frontend

## Migration from Custom OAuth

If you were using the old custom OAuth system (`useOAuth`), the migration is simple:

```javascript
// Before (custom OAuth)
import { useOAuth } from "../../../framework/hooks/useOAuth.js";
const { isConnected, initiateOAuth } = useOAuth("google");

// After (Nango)
import {
  useNangoOAuth,
  NangoIntegrations,
} from "../../../framework/hooks/useNangoOAuth.js";
const { isConnected, connect } = useNangoOAuth(NangoIntegrations.googleMail);
```

Backend functions:

```javascript
// Before
const { getOAuthToken } = require("./lib/oauth-utils.js");
const token = await getOAuthToken(userId, "google", context);

// After
const { getOAuthToken } = require("./lib/nango-utils.js");
const token = await getOAuthToken(userId, "google-mail", context);
```
